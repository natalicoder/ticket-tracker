# План: Kanban-трекер тикетов для хакатона

## Контекст
Задание: `Hackathon_Ticketing_System_Requirements_v4 1.docx`. Нужен трёхуровневый Kanban-трекер: SPA, HTTP API и PostgreSQL, запуск одной командой `docker compose up --build` на любой ОС. QA будет проверять по разделу 13 (Definition of Done). Папка `C:\Projects\Code Jam` пока пустая, начинаем с нуля.

**Цель:** закрыть 100% требований и выделиться среди участников. Срок 1–2 дня, код пишет Claude.

**Приоритеты (по убыванию):**
1. Ни одного проваленного пункта спеки, включая edge-кейсы.
2. Инженерное качество: тесты, e2e, CI, OpenAPI, матрица трассировки требований.
3. UX: продуманная доска, command palette, горячие клавиши, тёмная тема.
4. Официальные stretch-фичи из раздела 14.

**Не делаем:**
- AI-фичи: ключа нет.
- Всё из раздела 12: уведомления, realtime, дашборды, роли и т. п. Это засчитают как выход за рамки задания.

## Docker Compose (запуск с чистого checkout)
- `secrets-init`: одноразовый alpine-контейнер. Генерирует случайный пароль БД в named volume, если его там ещё нет. Postgres читает его через `POSTGRES_PASSWORD_FILE`, API через `DATABASE_PASSWORD_FILE`. **В репозитории нет ни одного секрета** (пункт DoD), при этом `.env` для старта не нужен.
- `db`: postgres:16-alpine с healthcheck, порт наружу не публикуется.
- `mailpit`: принимает SMTP на 1025, веб-интерфейс на http://localhost:8025. Здесь QA видит письма верификации.
- `api`: при старте применяет миграции Drizzle и запускается только после того, как db прошла healthcheck. Есть `/api/health` и `/api/ready`.
- `web`: nginx отдаёт собранную SPA и проксирует `/api` в api. Один origin, поэтому cookie работают без CORS. Адрес: http://localhost:8080.
- SMTP настраивается через env: `SMTP_HOST/PORT/SECURE/USER/PASS`, `MAIL_FROM`, `APP_BASE_URL`. По умолчанию письма уходят в Mailpit. В README есть готовый блок для `relay1.dataart.com`.
- Seed-данных нет совсем. Свежая БД содержит только схему и метаданные миграций.

## Схема БД (одна SQL-миграция Drizzle и триггеры)
- `users`: id uuid, email (хранится в trim+lower; уникальный индекс по `lower(email)`), password_hash (argon2id), email_verified_at, created_at.
- `sessions`: id = sha256 от случайного токена, user_id, expires_at. Токен лежит в httpOnly-cookie с `SameSite=Lax` и никогда не попадает в URL.
- `email_tokens`: user_id, token_hash, purpose (`verify` | `reset`), expires_at (+24 ч), used_at. При выдаче нового токена прежние неиспользованные токены того же purpose гасятся.
- `teams`: id, name, created_at, modified_at; уникальный индекс по `lower(btrim(name))`.
- `epics`: id, team_id (FK RESTRICT), title, description, timestamps; `UNIQUE(id, team_id)`.
- `tickets`: id serial (отображается как `#123`), team_id, type, state (CHECK по enum), epic_id, title, body, created_at, modified_at, created_by.
  - **Составной FK `(epic_id, team_id) → epics(id, team_id)`**: правило «эпик той же команды» соблюдается на уровне БД, а не только в сервисе.
  - **BEFORE UPDATE триггер** меняет `modified_at = now()`, только если бизнес-поля `IS DISTINCT FROM` старых. Сохранение без изменений не сдвигает метку.
- `comments`: id, ticket_id (FK CASCADE), author_id, body, created_at, edited_at (для stretch). Ticket не трогает.
- `ticket_events` (stretch, история активности): ticket_id (CASCADE), actor_id, kind, field, from, to, at. Пишется в той же транзакции, что и изменение тикета.
- Удаление team/epic с зависимыми записями отклоняется FK RESTRICT; сервис заранее проверяет зависимости и возвращает **409** с понятным текстом.

## API (префикс `/api`, единый формат ошибки `{error:{code,message,details}}`)
- Auth (публичные): `POST /auth/signup`, `POST /auth/login`, `POST /auth/logout`, `POST /auth/verify` (токен в body), `POST /auth/resend-verification` (всегда 202, чтобы нельзя было перебирать email), `GET /auth/me`. Stretch: `POST /auth/forgot-password`, `POST /auth/reset-password`.
  - Ссылка в письме ведёт на SPA `/verify?token=…`, а SPA делает POST. Так почтовые сканеры, которые открывают ссылки заранее, не «съедают» одноразовый токен.
  - Вход неверифицированного пользователя: 403 `EMAIL_NOT_VERIFIED`, в UI появляется кнопка «Отправить письмо ещё раз».
  - На auth-эндпоинтах включён rate-limit.
- Teams: `GET /teams` (со счётчиками tickets/epics для disabled-кнопок удаления), `POST`, `PATCH /teams/:id`, `DELETE` (409).
- Epics: `GET /epics?teamId=` (со счётчиком тикетов), `POST`, `PATCH /epics/:id` (teamId менять нельзя: 400), `DELETE` (409).
- Tickets: `GET /teams/:id/tickets` (лёгкий список для доски, сортировка modified_at desc), `GET /tickets/:id`, `POST /tickets`, `PATCH /tickets/:id`, `PATCH /tickets/:id/state` (для DnD), `DELETE /tickets/:id`.
- Comments: `GET/POST /tickets/:id/comments` (oldest first). Stretch: `PATCH/DELETE /comments/:id`, только свои.
- Events (stretch): `GET /tickets/:id/events`.
- Коды ответов: 400 (валидация zod, в т. ч. enum'ы и ссылки), 401, 403, 404, 409. Все timestamps отдаются в ISO-8601 UTC (`toISOString`).
- Swagger UI на `/api/docs`, генерируется из zod-схем.
- Защита от CSRF: `SameSite=Lax` плюс обязательный `Content-Type: application/json` у мутаций.

## Frontend (экраны из раздела 10 и сверх него)
- **Публичные экраны:** Sign up, Login (с resend), Verify result (успех, истёк, использован; resend), stretch: Forgot/Reset password.
- **Доска:** селектор команды (последняя выбранная запоминается, но хранится только как удобство), 5 колонок в порядке workflow с человекочитаемыми лейблами и счётчиками.
  - Карточка показывает `#id`, title, цветной бейдж type, чип epic и относительное время изменения.
  - DnD на dnd-kit с поддержкой клавиатуры (accessibility). Обновление оптимистичное; при ошибке карточка возвращается в прежнюю колонку и показывается toast с ошибкой.
  - Фильтры type, epic (включая «без эпика») и поиск по title без учёта регистра объединяются по AND и хранятся в query-параметрах URL, так что ссылкой можно поделиться.
  - Колонки виртуализируются (stretch), доска проверена на 300+ тикетах.
- **Тикет:** маршрут `/tickets/:id` открывается боковой панелью поверх доски, на него можно дать прямую ссылку.
  - Показываются все поля, включая created by/at и modified at.
  - Редактирование: при смене команды эпик сбрасывается.
  - Body в Markdown с вкладкой превью (санитизированный react-markdown).
  - Комментарии с автором и временем, вкладка Activity (stretch).
  - Удаление после подтверждения в диалоге.
- **Teams / Epics:** таблицы с inline-созданием и переименованием. Кнопка удаления неактивна, а tooltip объясняет причину, например «Есть 3 тикета», как на wireframe. Если всё же пришёл 409, показываем понятное сообщение.
- **UX-фишки:**
  - Command palette по Ctrl/⌘+K: перейти к команде, найти тикет, создать тикет.
  - Горячие клавиши: `C` новый тикет, `/` поиск, `?` справка.
  - Тёмная и светлая темы.
  - Skeleton-загрузка, empty states с призывом к действию, toasts успеха и ошибки.
  - Меню пользователя с пунктом Log out.
- Визуальное направление продумываем при реализации через навык frontend-design.

## Вау-эффект без AI
Ориентир: уровень «как Linear». Каждая фича ниже не выходит за рамки раздела 12.

**«Умные» фичи, которые выглядят как AI, но работают на Postgres и детерминированной логике:**
1. **Поиск похожих тикетов при создании.** Включаем расширение `pg_trgm` и считаем `similarity(title)` в рамках команды. Пока пользователь вводит заголовок, под полем появляется подсказка «Похоже на #12 “Login fails on Safari” (82%)». Для этого нужен эндпоинт `GET /teams/:id/tickets/similar?q=`.
2. **Quick-add одной строкой.** Ввод `bug: Падает логин в Safari @auth` в колонке или в palette разбирается на type=bug, epic по префиксу `@` и title. Под полем сразу показывается превью распознанных полей в виде чипов. Тело тикета (body) спека требует обязательным, поэтому после ввода открывается форма, где title, type и epic уже заполнены, и фокус стоит на body.
3. **Возраст тикета в текущем состоянии.** На карточке есть индикатор «в In Progress 4 дня». Это информация по одной карточке, а не дашборд. Считается по `ticket_events`, а до появления событий по `modified_at`.

**Ощущение от доски:**
4. **Управление с клавиатуры:** `J/K/H/L` или стрелки переключают фокус между карточками, `Shift+←/→` переносят карточку в соседнюю колонку (это тоже сохраняется сразу), `Enter` открывает тикет, `E` переходит к редактированию.
5. **Undo после перемещения.** После переноса показывается toast «Moved to Done · Undo» на 5 секунд; Undo возвращает прежнее состояние через API.
6. **Плавная анимация DnD.** Карточка при перетаскивании слегка наклоняется и поднимается, колонка подсвечивается, карточки на месте вставки раздвигаются (layout-анимации). При переносе в Done проигрывается короткий салют, его можно выключить в меню. Поддержан `prefers-reduced-motion`.
7. **Чеклисты в Markdown.** Если в body есть `- [ ]`, на карточке появляется прогресс «2/5»; галочки в превью можно кликать, и это сохраняет body.

**Первое впечатление:** QA начинает с пустой БД, поэтому этот пункт особенно важен.
8. **Мастер первого запуска.** Пустая доска не выглядит пустой: на ней показаны 3 шага «Создайте команду → эпик → первый тикет» с кнопками, шаги отмечаются по мере выполнения.
9. **Оформленное HTML-письмо верификации** с текстовой версией. Если письмо уже ушло, на экране после регистрации видно, куда оно отправлено, и есть кнопка «Открыть Mailpit»; она показывается только в dev-режиме.

**Качество, которое видно:**
10. Адаптивная вёрстка вплоть до планшета. Доступность по WCAG AA: фокус-кольца, aria-атрибуты для DnD, контраст в обеих темах. Цель Lighthouse по Accessibility не ниже 95.
11. В README есть GIF или короткое видео демо-сценария и раздел «Сценарий демо за 3 минуты» для защиты.

Все вау-фичи покрываются тестами: unit-тесты для парсера quick-add, API-тест для similar и e2e-тест для переноса с клавиатуры и Undo.

## Тесты и качество
- **API (Vitest + реальный Postgres из `docker-compose.test.yml`):**
  - Полный auth-flow: signup → письмо перехватывается тестовым транспортом → verify → login. Плюс одноразовость и истечение токена, инвалидация старого токена при resend, email без учёта регистра.
  - Правило «эпик из той же команды»: проверка и в сервисе, и в FK.
  - No-op save не меняет modified_at; комментарий его тоже не меняет.
  - 409 при удалении команды или эпика с зависимостями; уникальность имени команды.
  - 401 на каждом приватном эндпоинте (табличный тест по списку роутов).
  - Свежая БД пуста после миграций.
- **Web (Vitest + RTL):** логика фильтров, rollback при ошибке DnD.
- **E2E (Playwright против поднятого compose):** регистрация → письмо забирается через API Mailpit → верификация → логин → команда → эпик → тикет → DnD → reload → состояние сохранилось → комментарий.
- **CI в GitHub Actions:** lint, typecheck, unit/API-тесты, `docker compose up --build`, e2e.
- **README:**
  - prerequisites, быстрый старт, URL'ы (приложение, Mailpit, Swagger);
  - таблица env и блок для relay1.dataart.com;
  - запуск тестов;
  - mermaid-диаграмма архитектуры;
  - **матрица трассировки:** каждый пункт спеки → где реализован → какой тест его проверяет. Главный козырь для QA.

## Решения, принятые мной (можно поправить)
- secrets-init вместо пароля БД в compose: так DoD «нет committed secret» выполняется буквально.
- Числовые ID тикетов (`#123`) вместо UUID: так их удобнее показывать на доске.
- Верификация через POST из SPA, а не через GET-ссылку на API: это защищает одноразовый токен от почтовых сканеров.
- История активности несмотря на «audit history» в разделе 12: она явно перечислена в stretch (раздел 14).
